== 1. 引言与目标

=== 1.1 需求概览

Claw-Pi 有多个用户入口：龙虾大脑、微信/飞书等渠道、网页龙虾、龙虾工作台。当前目标是让龙虾工作台也成为 OpenClaw agent 客户端，而不是绕过 OpenClaw 直接调用 OpenAI-compatible `/v1/chat/completions`。

目标运行方式：

[source,text]
----
用户界面
  -> Claw-Pi Controller
  -> OpenClaw Gateway / Agent Session
  -> 云雾模型大脑/模型供应商
  -> OpenClaw 工具、文件、技能、权限、记忆
  -> Claw-Pi UI 展示结果
----

=== 1.2 当前完成状态

已完成：

* 龙虾工作台通过 Controller 的 `AgentChatService` 调用 OpenClaw `agent` runner。
* 默认对话模型固定使用 `link/gpt-5.5`。
* 默认生图模型固定使用 `clawpi-image/gpt-image-2`。
* 生图能力经 `clawpi-image-generation` runtime plugin 调回 Controller 生图接口。
* 工作台 SSE 响应头立即返回，避免 OpenClaw 冷启动期间前端表现为无响应。
* 工作台 agent run 使用 `bootstrapContextMode="lightweight"`，跳过 AGENTS/SOUL/BOOTSTRAP/MEMORY 首轮注入，避免 onboarding 干扰普通问答。
* Controller 会等待 OpenClaw 空 final 后的同 session 内层 run，避免过早结束导致 UI 显示“没有收到有效回复”。
* OpenClaw pricing bootstrap 可通过 `OPENCLAW_SKIP_MODEL_PRICING=1` 禁用，避免首条请求被 OpenRouter 价格表超时拖慢。
* OpenClaw WS 首次 connected 后只在断连期间发生配置写入时触发 `syncAll()`，避免启动阶段重复 reload。
* OpenClaw sidecar 在 `models.mode="replace"` 且已有显式供应商模型时，跳过隐式 provider discovery，并直接从 Claw-Pi 编译出的 `models.providers` 构建 model catalog。

=== 1.3 质量目标

[cols="1,3",options="header"]
|===
|目标 |说明

|可用性
|龙虾工作台、龙虾大脑、微信问答、生图不能互相破坏。

|一致性
|工作台对话和渠道对话使用同一套模型配置和 OpenClaw runtime 能力。

|响应速度
|SSE 连接必须快速建立；OpenClaw 稳定态简单回复应控制在可接受范围，当前 warm 验证约 12 秒完成，UI 来源请求首 token 约 6.6 秒。

|可执行能力
|工作台应能使用 OpenClaw 提供的文件、工具、技能、执行权限，而不是普通聊天代理。

|可回归
|测试默认只使用 `gpt-5.5`；生图只使用 `gpt Image2`，避免模型切换造成误判。
|===

== 2. 架构约束

* OpenClaw 是 runner，不是模型；它需要接入现有模型大脑作为对话/推理模型。
* 不能替换云雾模型供应商，只能复用当前模型配置和账号余额。
* 不能移除 `/v1/chat/completions`，该接口仍作为兼容和诊断路径存在。
* 工作台用户回复不能静默绕回直连模型路径。
* 打包产物必须在 `apps/desktop/release/win-unpacked` 可运行。
* Windows 环境下不能依赖系统 Node 版本，OpenClaw sidecar 优先使用 Electron Node。
* 不输出或提交 API key、账号 token、云雾配置明文。

== 4. 解决方案策略

* Controller-first：Controller 仍是本地控制面，负责读取 Claw-Pi 配置、编译 OpenClaw 配置、启动 OpenClaw、同步模型和渠道。
* OpenClaw-backed workbench：工作台新增 `AgentChatService`，将用户消息包装成权限约束后发送给 OpenClaw `agent`。
* SSE compatibility：对前端保持 OpenAI-compatible stream 形态，内部事件来自 OpenClaw `chat` event。
* Lightweight workbench turns：工作台请求显式传 `bootstrapContextMode="lightweight"` 和 `extraSystemPrompt`，保留 runner/tool 能力，同时避免新工作区 bootstrap 文档抢占用户消息。
* 固定默认模型：测试和默认路径只使用 `link/gpt-5.5`；生图固定 `clawpi-image/gpt-image-2`。
* Sidecar patch：OpenClaw 上游包通过 `prepare-openclaw-sidecar.mjs` 打补丁，确保打包产物可重复生成。
* 冷启动体验修复：即使 OpenClaw WS 尚未 connected，Controller 也先返回 SSE stream，再在后台等待 gateway ready。
* Replace-mode catalog fast path：当 Claw-Pi 已经把云雾/Link 模型写进 OpenClaw config 的显式 providers 时，OpenClaw 不再扫描隐式供应商或 provider plugin catalog，直接使用显式列表。

== 6. 运行时视图

=== 6.1 工作台对话

[source,text]
----
Workbench UI
  -> POST /api/internal/agent-chat/stream
  -> AgentChatService creates SSE immediately
  -> wait until OpenClaw WS connected if needed
  -> ws.request("agent", sessionKey, message, thinking="off", bootstrapContextMode="lightweight")
  -> OpenClaw dispatches agent turn
  -> Model provider link/gpt-5.5
  -> OpenClaw emits chat delta/final
  -> Controller maps events to SSE chunks
  -> UI renders assistant reply
----

生图请求属于同一条工作台 Agent 流。runtime plugin 调用 Controller 时不能使用短于 Agent 流生命周期的固定超时；当前 Controller 请求和 Agent Chat 均使用 600 秒上限。生成成功后，plugin 将 `markdown`、`mediaUrl` 和本地 `filePath` 放入 tool details，`AgentChatService` 从 tool details 提取图片 Markdown 并继续通过同一条 SSE 返回。

=== 6.2 生图

[source,text]
----
User asks image generation
  -> OpenClaw tool image_generate
  -> clawpi-image-generation runtime plugin
  -> Controller /api/internal/desktop/images/generations
  -> cloud image model clawpi-image/gpt-image-2
  -> generated image stored under nexu-home/generated-images
  -> markdown image URL returned to UI
----

=== 6.3 OpenClaw 启动

[source,text]
----
Desktop starts Controller
  -> Controller writes OpenClaw config
  -> OpenClawProcessManager spawns OpenClaw
  -> env includes OPENCLAW_SKIP_MODEL_PRICING=1
  -> Controller WS client retries until gateway is ready
  -> workbench stream waits internally if user sends message early
----

=== 6.4 Model Catalog 快路径

[source,text]
----
Controller compileModelsConfig
  -> OpenClaw config models.mode = "replace"
  -> OpenClaw config models.providers.link.models includes gpt-5.5
  -> patched models-config skips implicit provider discovery
  -> patched model-catalog builds entries directly from explicit providers
  -> OpenClaw agent selects link/gpt-5.5
  -> nexu-runtime-model calls 云雾/Link model API
----

这个路径只影响 OpenClaw sidecar 的模型发现阶段，不改变龙虾大脑、微信/飞书渠道和 `/v1/chat/completions` 的兼容路径。

=== 6.5 隐式 main agent 鉴权同步

[source,text]
----
Controller compiles OpenClaw config
  -> agents.list contains explicit agents
     -> write provider auth profiles to each explicit agent workspace
  -> agents.list is empty
     -> Workbench chat resolves the missing agent to "main"
     -> write the same provider auth profiles to agents/main/agent/auth-profiles.json
----

OpenClaw 允许不声明 `agents.list`，此时工作台聊天仍使用隐式 `main` agent。鉴权同步必须覆盖这个隐式 workspace，否则模型配置中虽然已有 API Key，运行时仍会因 `main` 缺少 `auth-profiles.json` 而无法调用模型。

=== 6.6 投喂页余额查询

[source,text]
----
Recharge UI
  -> Controller GET /api/internal/activation/balance
  -> Claw-Pi cloud GET /api/auth/balance with activation JWT
  -> return balance and cumulative recharge when available

If the cloud balance request fails:
  -> Controller reads the locally stored activation API key
  -> Yunwu GET /v1/dashboard/billing/subscription
  -> Yunwu GET /v1/dashboard/billing/usage
  -> calculate balance_cents = hard_limit_usd * 100 - total_usage
  -> return the current balance without exposing or logging the API key
----

该兜底只补充当前余额，不伪造累计充值金额。若两条路径都失败，投喂页保留在当前页面并提供重新加载，不触发账号断开或重新登录。

=== 6.7 桌面客户端自动更新

[source,text]
----
Developer runs pnpm release:desktop from the reviewed development branch
  -> local health checks pass before the package version is changed
  -> the command commits and force-pushes the branch to GitHub
  -> the command creates an immutable v{version} tag on that remote source commit
  -> desktop-release checks out the tag and runs source-health
  -> desktop-release builds the Windows NSIS installer in GitHub Actions
  -> CI validates manifests, referenced files, hashes, blockmaps, and checksums
  -> CI uploads immutable Windows artifacts to both feed prefixes
  -> CI uploads latest.yml to both prefixes only after immutable uploads complete
  -> CI reads both public Windows feeds and verifies every required artifact
  -> GitHub Release changes from draft to published
  -> installed client checks immediately and every 15 minutes
  -> electron-updater downloads the update in the background
  -> user restarts immediately, or the update installs on normal app exit
----

桌面发布不要求 Ubuntu API 服务器检出或运行 Electron 源码，也不触发服务端进程重启。GitHub 中的远程提交和不可变版本标签是生产构建的唯一源码真相。服务端更新域名只暴露 Cloudflare R2 中的静态更新产物；当前默认只构建 Windows，macOS 仅在显式手动全平台发布时进入 Apple 签名和公证流程。

== 7. 部署视图

Windows 本地开发验收可使用 portable 目录，正式发布使用 NSIS 安装包：

* 可执行文件：`apps/desktop/release/win-unpacked/Claw-Pi.exe`
* Controller bundle：`resources/runtime/controller/dist/index.js`
* OpenClaw sidecar：`resources/runtime/openclaw/node_modules/openclaw`
* 用户数据：`apps/desktop/release/win-unpacked/data`
* OpenClaw 状态：`data/user-data/runtime/openclaw/state`
* Claw-Pi 配置：`data/nexu-home`

正式 Windows 发布产物：

* 安装包：`claw-pi-setup-{version}-x64.exe`
* 差分升级元数据：`latest.yml`
* 差分升级块映射：`claw-pi-setup-{version}-x64.exe.blockmap`
* 校验文件：`desktop-win-x64-sha256.txt`
* R2 更新源：`{channel}/win/x64`

已安装的 NSIS 客户端默认启用自动更新并在后台下载新版本；下载完成后可以由用户立即重启安装，也会在应用正常退出时自动安装。portable 构建不进入自动更新链路。运维可通过 `NEXU_DESKTOP_AUTO_UPDATE_ENABLED=false` 显式关闭已安装客户端的自动更新。

R2 发布使用 S3 兼容 API。小文件使用普通 `PutObject`，超过 64 MiB 的 Windows
安装包自动使用 multipart upload，避免 Wrangler 单文件上传限制。GitHub Actions
需要 `CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_R2_ACCESS_KEY_ID` 和
`CLOUDFLARE_R2_SECRET_ACCESS_KEY` 三个 secrets；这些凭据只存在于 Actions 环境，
不进入桌面客户端或仓库文件。

Windows 开发模式下，`prepare-openclaw-sidecar.mjs` 使用目录 junction 复用 runtime 依赖，并排除 `.package-lock.json` 等需要文件符号链接权限的 npm 元数据。传给 Controller 和 OpenClaw 的状态、技能目录必须由 `userDataPath` 生成绝对路径，不能把未展开的 `~` 再交给 `path.resolve`。runtime 完整性检查覆盖 OpenClaw 入口及关键传递依赖（例如 `chalk`）；缺失时必须重新安装 runtime，不能复用残缺目录。

Electron webview 的 preload 由主进程在 `will-attach-webview` 阶段注入本地文件路径。渲染层不能基于开发服务器的 `http:` 地址拼接 preload URL，否则 Electron 会拒绝加载该桥接脚本。

打包命令：

[source,powershell]
----
$env:NEXU_DESKTOP_USE_EXISTING_BUILDS='1'
$env:NEXU_DESKTOP_USE_EXISTING_RUNTIME_INSTALL='1'
$env:NEXU_DESKTOP_ARCHIVE_OPENCLAW_SIDECAR='0'
pnpm --filter @nexu/desktop dist:win:portable
----

当前正式发布由根目录 `pnpm release:desktop` 驱动。命令在版本变更前执行类型检查、Windows 发布相关根目录测试、Controller 测试、构建和 ESM 引用检查，随后更新桌面版本、提交全部已审阅源码并强制推送当前开发分支，再创建不可变 `v{version}` 标签。Windows 发布测试门禁排除 `data-directory-runtime.test.ts`、`lifecycle-teardown.test.ts`、全部 `*launchd*.test.ts`、全部 `*plist*.test.ts` 和 `entitlements-plist.test.ts` 这些依赖 macOS launchd、Apple plist 或 POSIX 路径语义的专属测试；日常完整测试命令保持不变。标签触发 `.github/workflows/desktop-release.yml`；`source-health` 从标签重新检出并验证源码，Windows runner 构建 NSIS x64 安装包。流水线先把安装包、`.blockmap` 和 SHA-256 上传到 `{channel}/win/x64` 与兼容前缀 `{channel}/x64`，两个前缀都完成后才分别上传 `latest.yml`。只有两个公网更新源都返回目标版本且所有必需对象均可访问，GitHub Release 才从草稿转为正式发布。发布失败时客户端继续读取上一版清单；回滚也必须最后恢复上一版更新清单。

本地 `main` 当前与 `origin/main` 存在未整理的历史分歧，因此发布命令显式拒绝本地 `main`，避免错误覆盖主分支。短期内，已审阅开发分支的远程提交加不可变标签承担生产源码真相；历史对齐完成后，可恢复 `.github/workflows/desktop-auto-tag.yml` 的常规 `main` 自动打标签路径。

根目录 `prepare` 脚本使用 Node.js 安装 Git hooks，并在 Git 元数据不可用时容忍跳过，确保 Windows runner 和无 `.git` 的归档构建不会因 Unix 专用 `cp/chmod` 命令失败而阻断桌面发布。

== 8. 横切概念

=== 8.1 权限模式

工作台支持 `basic`、`confirm`、`full` 三档权限。默认 `full`，但破坏性操作仍需保护。权限约束由 Controller 注入到用户消息前面。

=== 8.2 Session Key

工作台 session 映射为：

[source,text]
----
agent:{agentId}:workbench:{sessionId}
----

该 key 必须稳定，才能让 OpenClaw 恢复同一会话上下文。

=== 8.3 模型选择

默认模型来自桌面当前选择；若未设置，则回退到 bot 模型或 runtime 默认模型。当前测试要求只使用：

* 对话：`link/gpt-5.5`
* 生图：`clawpi-image/gpt-image-2`

=== 8.4 Latency 分层

必须区分：

* HTTP/SSE header 建立时间。
* OpenClaw WS request ack 时间。
* OpenClaw session-init/dispatch 时间。
* LLM 首字时间。
* OpenClaw final event 到 UI 完成时间。

== 9. 架构决策

=== ADR-001: 工作台走 OpenClaw runner

*状态：已采纳*

原因：工作台需要本机执行权、文件处理、技能、工具和 OpenClaw session。直连 `/v1/chat/completions` 只能提供普通聊天。

结果：新增 Controller `AgentChatService`，使用 OpenClaw `agent` runner。

=== ADR-005: 工作台使用 OpenClaw `agent` 方法并启用 lightweight bootstrap

*状态：已采纳*

原因：`chat.send` 是 WebChat 专用 schema，不接受 `extraSystemPrompt` 和 `bootstrapContextMode`。工作台需要跳过新工作区 bootstrap/onboarding 上下文，同时保留 OpenClaw runner、工具和会话能力。

结果：工作台改为调用 OpenClaw `agent` 方法；sessionKey 继续使用 `agent:{agentId}:workbench:{sessionId}`；请求设置 `deliver=false`、`thinking=off`、`bootstrapContextMode=lightweight`。

=== ADR-002: 保留兼容直连模型接口

*状态：已采纳*

原因：龙虾大脑、诊断工具和旧路径仍依赖 OpenAI-compatible 接口。

结果：工作台迁移不删除 `/v1/chat/completions`。

=== ADR-003: 禁用 OpenClaw pricing bootstrap

*状态：已采纳*

原因：OpenRouter pricing catalog 网络超时会阻塞首条工作台消息。

结果：OpenClaw sidecar patch 支持 `OPENCLAW_SKIP_MODEL_PRICING=1`，Controller 启动 OpenClaw 时注入该环境变量。

=== ADR-004: SSE 先建立，再等待 OpenClaw ready

*状态：已采纳*

原因：OpenClaw 冷启动或 WS 鉴权可能耗时较长，若 Controller 在返回 Response 前等待，会让 UI 看起来无响应。

结果：`AgentChatService` 创建 `ReadableStream` 后立即返回 Response，后台等待 Gateway connected。

=== ADR-006: 空 agent 列表同步隐式 main 鉴权

*状态：已采纳*

原因：工作台聊天在没有活动 bot 时会自动选择 `main`，而 OpenClaw 配置可合法省略 `agents.list`。仅遍历显式 agent 会漏写 `main` 的 `auth-profiles.json`，造成“配置中已有 API Key，但聊天鉴权不可用”。

结果：鉴权 writer 优先同步所有显式 agent workspace；当列表为空时，改为同步 `agents/main`。显式列表存在时不额外创建无关鉴权副本。

=== ADR-007: 余额查询使用用户账单接口作为本地兜底

*状态：已采纳*

原因：云端余额聚合依赖管理令牌；管理令牌被上游限流或临时封禁时，用户 API key 和模型调用仍可能完全正常。把该错误解释为登录失效会造成不必要的账号重连，且无法恢复余额展示。

结果：Controller 先请求云端余额接口；失败时使用本地激活 API key 查询云雾 subscription 和 usage，计算当前余额。API key 不进入日志或响应，前端仅在两条路径都失败时展示可重试的临时故障。

=== ADR-008: Windows 安装版使用独立自动更新源

*状态：已采纳*

原因：macOS 已使用 `{channel}/{arch}` 更新源，Windows 的 `latest.yml` 和 NSIS 产物不能与 `latest-mac.yml`、DMG/ZIP 混放。portable 目录也不具备可靠的安装替换语义。

结果：macOS 保持既有更新源不变；Windows x64 安装版使用 `{channel}/win/x64`，默认启用自动更新。portable 构建明确禁用自动更新，只用于本地验证或人工分发。

=== ADR-009: Restricted local Markdown image rendering for live generation results

*Status: accepted*

Reason: live WebChat replies arrive at the Control UI as Markdown text. The existing renderer only emitted `<img>` for `data:image/...`, so a successfully generated Claw-Pi image URL was shown as plain alt text while historical messages still worked through structured media blocks.

Result: the sidecar preparation step patches the Control UI bundle to allow only loopback URLs under `/api/internal/desktop/generated-images/` with common image extensions. Arbitrary remote HTTP images remain text, `data:` images remain supported, and the bundle entry query key is incremented so browsers do not reuse the previous patched asset.

=== ADR-011: 桌面版本号驱动 CI 自动发布

*状态：已采纳*

原因：远程 Ubuntu 服务端不具备 Windows/macOS Electron 的签名构建环境，直接让服务器拉取本地源码也无法向已安装客户端分发可验证的安装包。与此同时，任何普通代码 push 都自动发布会把未准备好的变更推送给全部用户。

结果：服务器只托管更新静态产物；GitHub Actions 负责多平台构建、签名、公证和发布。只有 `main` 上桌面版本号单调递增才自动创建发布标签。更新清单是最后写入的发布指针，公网反向验证通过后才公开 GitHub Release。

|portable 目录没有稳定安装位置，自动替换可能损坏人工维护的数据或程序文件。
|portable 构建始终关闭自动更新；只有 NSIS 安装版默认进入自动更新链路。

|The prepare script increments the Control UI asset cache key and release validation checks the generated-image allowlist in the bundled asset.

=== Windows update delivery note (2026-07-30)

The Windows update endpoint at `https://api.clawpi.app:9443/updates/` is
served by Nginx as an HTTP 302 redirect to the public Cloudflare R2 bucket.
The Ubuntu server does not proxy or buffer release binaries. This avoids
making desktop update availability depend on the server's outbound TLS path
to R2 while keeping the existing client feed URL stable.

This delivery decision currently applies to Windows only. macOS update
delivery remains outside the scope of this change.

=== Windows legacy update feed compatibility (2026-07-31)

Early Windows clients requested the shared `${channel}/x64` feed before the

== ADR-010: HTTP listening is not business readiness

*Status:* accepted

The packaged desktop can observe the Controller port before the OpenClaw
Gateway WebSocket handshake completes. Treating any HTTP 200 response as
ready lets the web image-generation plugin call the Controller during this
window and surface a misleading connection failure.

The ready endpoint keeps HTTP 200 for polling compatibility but reports
`ready=false` until runtime health, runtime state, Gateway WS handshake, and
model state are all ready. The desktop launchd probe parses the JSON field and
continues polling.

== Architecture reliability addendum (2026-07-30)

=== 4. Solution strategy

The workbench treats a long-running agent request as a streaming operation,
not as a short HTTP request. The Controller emits periodic SSE heartbeat
comments, preserves structured stream errors, and retries an empty final
completion once when the upstream session is still usable. The desktop web
sidecar allows up to 900 seconds for the agent stream so a slow tool workflow
is not converted into a client-side timeout.

The web workbench applies a deterministic context budget before sending an
agent request. The current user task has highest priority and remains complete
unless that task alone exceeds the budget. Remaining capacity is allocated to
the session summary, enabled knowledge, and recent conversation in that order.
Session compaction is serialized per session and the next request reloads the
shared session cache after compaction completes.

=== 6. Runtime flow

The agent request path is:

. Web workbench waits for any compaction already running for the target session.
. Web workbench reloads the latest session snapshot and builds bounded context.
. Controller opens or reuses the OpenClaw Gateway WebSocket session.
. Controller forwards SSE heartbeats and structured errors while the agent runs.
. OpenClaw WebSocket disconnects are propagated to the waiting request.
. Web workbench renders stream deltas and turns a non-empty error or error
  finish reason into an explicit failed assistant message.

Both the normal SSE loop and the trailing buffered chunk accept delta content,
message content, usage, finish reason, and structured error payloads.

=== 7. Deployment and packaging

The packaged desktop web sidecar uses a 900 second timeout for the agent
stream proxy. This value is intentionally longer than the normal UI request
timeout because OpenClaw may spend several minutes on file, browser, or
workspace operations while still producing heartbeat traffic.

=== 9. Architecture decisions

==== ADR-011: Preserve the current task under context pressure

*Status:* accepted

The workbench does not use a final tail slice of the assembled prompt. A tail
slice can remove the beginning of a long command and can also remove the
instruction that identifies the current user message. The implementation
allocates the budget by priority and only truncates the current task when the
task itself is larger than the maximum workbench message size.

==== ADR-012: Serialize session compaction

*Status:* accepted

Compaction is tracked as a promise per session rather than as a boolean set.
Concurrent sends wait for the same promise, then reload the shared session
snapshot. This prevents stale React closures from rebuilding a request with
pre-compaction history.

=== 10. Quality requirements

Long agent tasks must remain observable while they are active, must expose
upstream failures to the user, and must not lose the current task because of
historical context growth. Reliability verification covers controller stream
tests, Web TypeScript checking, Controller TypeScript checking, sidecar
syntax checking, and whitespace validation.

=== 11. Technical risks

The main residual risks are provider-specific SSE dialects, upstream account
concurrency limits, and model context limits that are smaller than the local
20,000 character workbench budget. A future improvement should add request
telemetry for context size, compaction wait time, first token latency, and
stream termination reason so production failures can be ranked from evidence.

=== Desktop release fallback

Tag pushes and the default manual dispatch skip the macOS matrix entirely.
The Windows job depends only on immutable source health and its own build,
artifact, public-feed, and release checks. macOS runs only when an operator
explicitly requests an all-platform manual release, so unavailable Apple
signing credentials cannot block the default Windows OTA path. The macOS update
feed remains on the previous verified signed release until a separate macOS
release succeeds.

=== ADR-021: Windows-first releases use tagged remote source truth

Context: the local development branch contains the reviewed Windows fixes while
the local and remote `main` histories are substantially divergent. Rewriting
`main` during a production release would mix repository reconciliation with OTA
delivery. macOS signing availability is also independent from Windows package
health.

Decision: `pnpm release:desktop` checks, commits, and force-pushes the current
non-main branch, then creates an immutable version tag. GitHub Actions checks
out that tag as the only build input. Tag pushes skip macOS by default. Windows
immutable artifacts reach both R2 prefixes before either `latest.yml` pointer
is updated, and both public feeds must validate before the GitHub Release is
published.

Consequences: a Windows release can complete without Apple credentials, the
server never receives hand-copied Electron source, and a published manifest
cannot reference artifacts missing from the compatibility prefix. The
repository still needs a separate, reviewed `main` history reconciliation.

== Windows cloud bootstrap reliability addendum (2026-07-31)

=== 4. Solution strategy

Windows packages carry the production `NEXU_CLOUD_URL` and `NEXU_LINK_URL`
values in `build-config.json`. The Electron runtime reads those values and
passes them to the Controller process. The Controller derives its default cloud
profile from that packaged environment, so a fresh installation does not fall
back to development or legacy service endpoints.

=== 6. Runtime flow

During startup and model refresh, the Controller requests the public curated
catalog and the authenticated supplemental catalog concurrently. An
authenticated HTTP 401 invalidates the local cloud session, removes the expired
API key from the compiled OpenClaw provider, and retains the public curated
models. The invalidation path does not restart OpenClaw merely because public
inventory remains available.

=== 7. Deployment and packaging

The Windows packaging step writes both cloud endpoints into
`resources/build-config.json`. Runtime manifests expose them to the Controller
as `NEXU_CLOUD_URL` and `NEXU_LINK_URL`. Release validation must verify these
fields in addition to the existing update-feed metadata.

=== 9. Architecture decisions

==== ADR-013: Quarantine expired desktop credentials

*Status:* accepted

When an authenticated model request returns HTTP 401, the Controller stores
only a SHA-256 fingerprint of the invalidated API key. A stale desktop snapshot
containing the same key is rejected during later bootstrap imports. A newly
activated or explicitly imported valid key clears the fingerprint.

==== ADR-014: Preserve the GPT-5.6 display alias

*Status:* accepted

`link/gpt-5.6` remains a deliberate display alias backed by
`link/gpt-5.5`. Selecting GPT-5.6 in the UI must continue to send GPT-5.5 to the
backend. This release does not change that model mapping.

=== 10. Quality requirements

Public and authenticated model catalogs must be fetched in parallel. With both
requests configured for a 10 second timeout, startup waiting is bounded by one
request window rather than two serial request windows. An expired credential
must leave the application initialized, visibly disconnected, and still able
to present the public curated model catalog.

=== 11. Technical risks

A hot-updated desktop can retain an expired API key in its desktop snapshot and
reintroduce it after the Controller has invalidated the cloud session. The
stored invalidation fingerprint prevents that exact credential from being
reimported without persisting the secret itself. Credential rotation remains
the recovery path for a genuinely expired token.

== Windows proxy and model-catalog resilience addendum (2026-08-04)

=== 4. Solution strategy

Electron keeps Chromium in system-proxy mode and resolves the actual Link model
catalog target before any Controller or OpenClaw sidecar starts. The resolved
HTTP proxy is converted into `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`, and
`NODE_USE_ENV_PROXY=1` for every managed child process. Loopback addresses are
always appended to `NO_PROXY` so local Controller and OpenClaw traffic never
leaves the machine.

An authenticated desktop cloud session also carries a minimal built-in chat
catalog containing `gpt-5.5`. Remote `/v1/models` data remains authoritative
when present. The built-in entry is used only when discovery omits that model or
temporarily fails; disconnected sessions do not receive the authenticated
fallback. The UI-only `link/gpt-5.6` alias continues to resolve to this backing
model.

=== 6. Runtime flow

. Electron applies the configured system or explicit proxy to its session.
. For system mode, Electron resolves `https://yunwu.ai/v1/models` through the
  Windows proxy resolver with a bounded timeout.
. The concrete proxy and loopback bypass list are injected into the Controller
  and OpenClaw manifests before either process starts.
. Controller enables Node environment-proxy support and uses bounded network
  requests for catalog and health operations.
. If authenticated model discovery is unavailable, Controller compiles the
  built-in `link/gpt-5.5` provider entry and runtime allowlist entry. The next
  successful discovery refresh replaces fallback metadata without duplicating
  the model.

=== 7. Deployment and packaging

The fix is distributed as desktop version `0.3.21`. GitHub Actions builds the
NSIS installer and uploads the installer, blockmap, checksum, and `latest.yml`
to the Cloudflare R2 stable Windows feed. The manifest is uploaded last and is
publicly verified before the GitHub release is finalized, so existing `0.3.20`
installations only observe a complete update.

=== 9. Architecture decisions

==== ADR-015: Resolve the OS proxy before sidecar startup

*Status:* accepted

The desktop application does not write `HKCU\Environment` and does not assume a
fixed local proxy port. Chromium's Windows/PAC resolver is the source of truth;
the resulting process-local environment is inherited only by Claw-Pi runtime
children.

==== ADR-016: Keep the backing chat model available during catalog outages

*Status:* accepted

`gpt-5.5` is part of the authenticated Claw-Pi cloud contract and is the backing
runtime identity for the GPT-5.6 display alias. A minimal local fallback avoids
removing both cards merely because model discovery timed out. Authentication is
still required, and an explicit HTTP 401 removes the API key and the fallback.

=== 10. Quality requirements

Proxy resolution must not add more than three seconds to cold start. Proxy
credentials must be redacted from logs and diagnostics. Unit tests cover PAC
result parsing, sidecar environment propagation, Node proxy activation,
loopback bypass, the authenticated empty-catalog fallback, and OpenClaw runtime
allowlist compilation.

=== 11. Technical risks

PAC rules can vary by destination, while child-process environment variables
can represent only one HTTP(S) proxy. Resolving the actual Link model endpoint
minimizes that mismatch. SOCKS-only system proxies are not converted because
the bundled Node fetch path supports HTTP(S) environment proxies; those users
must use a compatible HTTP proxy listener or a future explicit SOCKS agent.

== Cloud endpoint ownership and release guard addendum (2026-08-04)

=== 4. Solution strategy

The packaged Cloud and Link values are installation seeds, not runtime policy.
The Controller uses the packaged values only when it creates
`cloud-profiles.json` for the first time. Once that file exists, its stored
`Default` entry and the active profile named in `config.json` are authoritative
across application updates.

The current production seeds are `http://47.108.215.151:9080` for Cloud and
`https://yunwu.ai` for Link. Windows and macOS packaging share these defaults;
release workflows pass the same pair explicitly.

=== 6. Runtime flow

. On first launch, the Controller seeds `cloud-profiles.json` from the packaged
  endpoints.
. On later launches, the Controller normalizes and reads the stored profiles
  without replacing the stored `Default` entry.
. `desktop.activeCloudProfileName` selects the active stored profile. A missing
  name falls back to the stored `Default`, then to the build seed only if no
  stored default exists.
. Credential login maps transport failures to separate DNS, TLS, and timeout
  messages. HTTP 400, 401, and 403 responses are reported as credential
  rejection rather than network unreachability.

=== 7. Deployment and packaging

After electron-builder creates the unpacked application, the packaging process
reads `resources/build-config.json` from the produced app. Formal packages must
contain the approved production endpoint pair and cannot bypass validation.
The verifier resolves hostnames and probes both `/v1/models` endpoints with a
bounded timeout. Cloud must return HTTP 200; Link may return HTTP 200 or the
expected unauthenticated HTTP 401/403. DNS, TLS, timeout, and unexpected HTTP
failures stop the package job before publication.

=== 9. Architecture decisions

==== ADR-017: User profile state outranks packaged endpoint seeds

*Status:* accepted

An application update must not mutate a valid user-selected endpoint. Build
configuration owns only initial defaults; user profile storage owns all
subsequent endpoint selection.

==== ADR-018: Fail closed when formal endpoint validation fails

*Status:* accepted

A formal package with missing, stale, policy-violating, or unreachable Cloud or
Link endpoints is rejected. Local packages may explicitly skip the live probe,
but the skip flag is rejected when the build metadata identifies a formal
release.

=== 10. Quality requirements

Profile regression tests must cover an existing stored `Default` whose values
differ from the new package. Packaging tests must cover production defaults,
formal-package policy rejection, accepted probe statuses, and classified DNS
failures. Login tests must cover DNS, TLS, timeout, and credential rejection.

=== 11. Technical risks

The production Cloud seed is currently plain HTTP because it mirrors the active
deployed service. This protects availability but does not provide transport
confidentiality for credential login. Migrating Cloud to a verified HTTPS
origin remains a security requirement; the formal endpoint allowlist and probe
expectations must be updated atomically when that migration occurs.

== Config sync and Gateway restart coordination addendum (2026-08-04)

=== 4. Solution strategy

Controller owns the boundary between cloud configuration synchronization and
the user-visible Agent Chat lifecycle. Configurations are normalized into a
stable semantic object, including the built-in `xai` plugin default, and are
identified by a SHA-256 revision. Semantically unchanged candidates are not
written. All OpenClaw configuration and pending-state writes use a temporary
file followed by an atomic rename.

Reload classification is requested from the OpenClaw-side
`nexu.config.plan` Gateway method. The Controller does not maintain a reload
path table; if the planning method is unavailable or returns an error, it
conservatively treats every changed path as restart-required.

=== 5. Building blocks and ownership

`ConfigSyncCoordinator` owns Agent Chat admission, active stream and pending
request leases, the restart state machine, the latest pending revision, safe
apply/rollback, and readiness recovery. `OpenClawConfigWriter` owns normalized
atomic persistence. `OpenClawGatewayService` owns planning RPC calls and
Gateway configuration revision tracking. `AgentChatService` owns stable run
identity and post-disconnect run recovery.

=== 6. Runtime flow

. An Agent Chat acquires a coordinator lease before submission and releases it
  only after its final response is written, or after explicit failure,
  cancellation, or timeout cleanup.
. A hot-only candidate is atomically applied immediately. A restart-required
  candidate is atomically saved as pending state; later syncs replace it with
  the newest revision.
. In one serialized critical section, the coordinator confirms that active
  streams and pending submissions are both zero and closes chat admission.
. The coordinator applies the candidate, observes the Gateway disconnect,
  waits for port health plus Controller WebSocket reconnection and a successful
  readiness probe, then reopens admission.
. A `1012 service restart` disconnect is a recoverable lifecycle event.
  Controller reconnects, queries `agent.wait` by stable run ID, and reads
  `chat.history` or resumes observation. It never resubmits unless a future
  protocol can prove the run was never created.
. Restart observation/readiness failure rolls the live file back, retains the
  pending candidate, reopens admission, and suppresses an automatic retry loop.

There is deliberately no deferral deadline that can force a restart while a
chat lease is active. The workbench polls coordinator state and shows that the
configuration update will apply after the current task finishes.

=== 7. Deployment and packaging

The planning Gateway method is shipped from
`static/runtime-plugins/nexu-runtime-model` and is bundled by the normal
Controller build. No installed or packaged `dist` file is edited in place.
At application startup, persisted pending state is normalized and applied
before Gateway launch, then deleted only after the atomic write succeeds.

=== 9. Architecture decisions

==== ADR-019: Controller coordinates restart around the user-visible chat lifecycle

*Status:* accepted

OpenClaw's internal run drain is necessary but insufficient because the
Controller may still be waiting to deliver the final stream result. Controller
therefore owns the admission gate and chat leases and allows configuration
files that require restart to change only after the user-visible lifecycle is
idle.

==== ADR-020: Disconnect recovery is query-first and never blind-resubmit

*Status:* accepted

Stable request/run IDs make a reconnect safe. A service restart causes bounded
status/history recovery. Blindly sending `agent` again is prohibited because
it can duplicate tool side effects.

=== 10. Quality requirements

Configuration sync must not fail an active Agent Chat because of a planned
Gateway restart. Multiple pending syncs before drain must converge on the
latest revision and produce one restart. Semantic no-op syncs must produce no
write and no reload. Restart recovery is bounded, logs no credentials, and
must leave the Controller able to accept chats after rollback. Automated tests
cover deferral, coalescing, admission races, hot-only model changes, semantic
normalization, `1012` recovery, startup recovery, and restart failure.

=== 11. Technical risks

The OpenClaw-side planner rules must be kept compatible with the bundled
OpenClaw version; unknown paths intentionally fail safe to restart-required.
`agent.wait` currently reports lifecycle status while final content is obtained
from `chat.history`, so recovery depends on session history retention and uses
a timestamp/run-scoped bounded search. A future OpenClaw run-result endpoint
would remove that residual ambiguity.
