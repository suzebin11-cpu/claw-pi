== 1. 引言与目标

=== 1.1 需求概览

Claw-Pi 有多个用户入口：龙虾大脑、微信/飞书等渠道、网页龙虾、龙虾工作台。当前目标是让龙虾工作台也成为 OpenClaw agent 客户端，而不是绕过 OpenClaw 直接调用 OpenAI-compatible `/v1/chat/completions`。

目标运行方式：

[source,text]
----
用户界面
  -> Claw-Pi Controller
  -> OpenClaw Gateway / Agent Session
  -> 云雾模型大脑/模型供应商
  -> OpenClaw 工具、文件、技能、权限、记忆
  -> Claw-Pi UI 展示结果
----

=== 1.2 当前完成状态

已完成：

* 龙虾工作台通过 Controller 的 `AgentChatService` 调用 OpenClaw `agent` runner。
* 默认对话模型固定使用 `link/gpt-5.5`。
* 默认生图模型固定使用 `clawpi-image/gpt-image-2`。
* 生图能力经 OpenClaw `image_generate` 工具和 `clawpi-image-generation` runtime plugin 调回 Controller 生图接口；`gpt-image-2` 纯文生图使用流式图片请求和 `partial_images=1`，避免上游长时间无首包导致 60s socket 断连；图生图/改图走同步 `/v1/images/edits`，避开云雾 edit stream 的 SSE 兼容问题。
* 图生图/改图请求必须携带 `image_generate.inputImages`；插件检测到“基于上传/参考图片”的请求但未收到可用图片路径、URL 或 data URL 时，会阻断请求并返回明确错误，避免误走纯文生图。
* Web 龙虾大脑、龙虾工作台和微信端共享 OpenClaw 配置/凭证同步；agent 发送前只在未成功同步、同步失败或已有同步进行中时等待 preflight，避免稳定态每 10 秒重复写 OpenClaw 配置。
* 工作台 SSE 响应头立即返回，避免 OpenClaw 冷启动期间前端表现为无响应。
* 工作台 agent run 使用 `bootstrapContextMode="lightweight"`，跳过 AGENTS/SOUL/BOOTSTRAP/MEMORY 首轮注入，避免 onboarding 干扰普通问答。
* Controller 会等待 OpenClaw 空 final 后的同 session 内层 run，避免过早结束导致 UI 显示“没有收到有效回复”。
* OpenClaw `chat` event 返回模型/网络错误时，Controller 将其标准化为用户可见错误并结束 SSE，避免上游 `Connection error` 被前端误判为空回复。
* 工作台请求保留 `requestRoute` 兼容字段，但除 `image_generation` 外前端统一走 `write_agent`；旧客户端传入的 `chat`、`read_only_agent`、`basic`、`confirm`、`read_only` 在 Controller 内部都按完全访问/可写执行处理。
* OpenClaw agent 上下文预算采用保守默认：最近上下文保留 `keepRecentTokens=8000`，工作台附件提取正文最多注入 12000 字符，进度自动续跑最多 4 次，空回复重试仍保留 1 次。
* OpenClaw pricing bootstrap 可通过 `OPENCLAW_SKIP_MODEL_PRICING=1` 禁用，避免首条请求被 OpenRouter 价格表超时拖慢。
* OpenClaw WS 首次 connected 后只在断连期间发生配置写入时触发 `syncAll()`，避免启动阶段重复 reload。
* OpenClaw Gateway WS 鉴权会同时发送配置的 gateway token 和已配对的 device token，避免打包环境重启后因只携带 gateway token 触发 `NOT_PAIRED`。
* OpenClaw sidecar 在 `models.mode="replace"` 且已有显式供应商模型时，跳过隐式 provider discovery，并直接从 Claw-Pi 编译出的 `models.providers` 构建 model catalog。
* Desktop shell 保持主 Web 工作台活跃态连续性；Web inactive 后延迟释放，OpenClaw 原生调试页按需挂载，降低隐藏 webview 常驻导致的 OOM 风险。

=== 1.3 质量目标

[cols="1,3",options="header"]
|===
|目标 |说明

|可用性
|龙虾工作台、龙虾大脑、微信问答、生图不能互相破坏。

|一致性
|工作台对话和渠道对话使用同一套模型配置和 OpenClaw runtime 能力。

|响应速度
|SSE 连接必须快速建立；OpenClaw 稳定态简单回复应控制在可接受范围，当前 warm 验证约 12 秒完成，UI 来源请求首 token 约 6.6 秒。

|可执行能力
|工作台应能使用 OpenClaw 提供的文件、工具、技能、执行权限，而不是普通聊天代理。

|可回归
|测试默认只使用 `gpt-5.5`；生图只使用 `gpt Image2`，避免模型切换造成误判。
|===

== 2. 架构约束

* OpenClaw 是 runner，不是模型；它需要接入现有模型大脑作为对话/推理模型。
* 不能替换云雾模型供应商，只能复用当前模型配置和账号余额。
* 不能移除 `/v1/chat/completions`，该接口仍作为兼容和诊断路径存在。
* 工作台用户回复不能静默绕回直连模型路径。
* 打包产物必须在 `apps/desktop/release/win-unpacked` 可运行。
* Windows 环境下不能依赖系统 Node 版本；packaged OpenClaw sidecar 必须优先使用随包发布的 standalone Node runtime，Electron-as-Node 仅作为兜底。
* 不输出或提交 API key、账号 token、云雾配置明文。

== 4. 解决方案策略

* Controller-first：Controller 仍是本地控制面，负责读取 Claw-Pi 配置、编译 OpenClaw 配置、启动 OpenClaw、同步模型和渠道。
* OpenClaw-backed workbench：工作台新增 `AgentChatService`，将用户消息包装成全能力执行约束后发送给 OpenClaw `agent`。
* OpenClaw-backed ask surface：网页龙虾/龙虾工作台的用户发送路径统一进入 `/api/internal/agent-chat/stream`，`/v1/chat/completions` 只保留为压缩、兼容和诊断路径。
* SSE compatibility：对前端保持 OpenAI-compatible stream 形态，内部事件来自 OpenClaw `chat` event。
* Lightweight workbench turns：工作台请求显式传 `bootstrapContextMode="lightweight"` 和 `extraSystemPrompt`，保留 runner/tool 能力，同时避免新工作区 bootstrap 文档抢占用户消息。
* Full-access agent prompt：前端除图片生成外统一发送 `write_agent`；Controller 兼容旧路由字段，但统一注入完全访问和可写执行提示。普通聊天仍走 OpenClaw runner，能直接回答就回答，需要本机/文件/网页/图片/命令能力时直接调用工具。
* Cost-aware context budget：OpenClaw agent 保留足够上下文以维持连续任务，但默认不再保留 20000 token 级别上下文；附件正文注入和执行类自动续跑都设置上限，降低长会话、长文档和工具循环的余额消耗。
* 固定默认模型：测试和默认路径只使用 `link/gpt-5.5`；生图固定 `clawpi-image/gpt-image-2`。
* GPT Image2 streaming：默认纯文生图使用 `stream=true` 和 `partial_images=1`，服务端明确拒绝 streaming 参数或返回 `406 openai_error` 时退回同步调用一次；图生图/改图固定同步调用 `/v1/images/edits`。
* Image input guard：`clawpi-image-generation` 插件在工具调用前记录 prompt/inputImages 参数摘要；若工具参数显示这是图生图/改图但 `inputImages` 为空，直接返回 `missing_input_images`，不调用云端纯文生图接口。
* WeChat QR state：微信扫码链路区分“二维码仍在等待手机端确认”和真实网络错误；`wait` 超时返回 pending 状态和明确提示，不再把未确认误导成桌面端网络故障。
* Gateway auth layering：Controller 连接 OpenClaw Gateway 时保留 configured gateway token 作为主 auth token，同时把本机已保存的 device token 作为 `auth.deviceToken` 发送，确保已配对设备不会在 scope-upgrade/admin runner 场景被误判为未配对。
* Sidecar patch：OpenClaw 上游包通过 `prepare-openclaw-sidecar.mjs` 打补丁，确保打包产物可重复生成。
* 冷启动体验修复：即使 OpenClaw WS 尚未 connected，Controller 也先返回 SSE stream，再在后台等待 gateway ready。
* Readiness 分层：`desktopReady`/`webReady` 只表示本地壳和 Web 可打开；`openclawReady` 表示 health + gateway WS；`agentReady` 再叠加模型状态。OpenClaw 原生页可被 `openclawReady` gate，Web 工作台不能被它全局阻塞。
* Runtime 自修复分级：OpenClaw exec 配置默认编译为 `host=auto`、`security=full`、`ask=off`。当 agent 返回 `exec host=node requires a paired node`、`exec host not allowed`、`/approve` 或 gateway not ready 时，Controller 先软修复并重试；只有确认执行状态损坏时才定向重启 OpenClaw，且带冷却时间，避免频繁让工作台进入“服务启动中”。
* Replace-mode catalog fast path：当 Claw-Pi 已经把云雾/Link 模型写进 OpenClaw config 的显式 providers 时，OpenClaw 不再扫描隐式供应商或 provider plugin catalog，直接使用显式列表。
* Runtime plugin atomic staging：Controller 写入 runtime plugins 时，临时 staging 放在 OpenClaw `extensions` 扫描目录之外，并清理历史 `.staging-*` 残留，避免 OpenClaw 把半成品目录当插件加载。
* Desktop surface lifecycle：用户主流程 Web 工作台活跃时保持挂载；inactive 超过保留窗口后释放 webview 进程。OpenClaw 原生页只在被激活时挂载。
* Cold-start branded wait：桌面壳优先停留在龙虾工作台启动界面。Windows 在申请 single-instance lock 前先清理同安装目录/同 `claw-pi-desktop` 上下文的旧 `Claw-Pi.exe`，随后固定清理 `50800`、`50810`、`18789` 的占用 PID，并继续使用固定端口；ready 超时不自动切到诊断/修复页，启动状态和诊断能力保留为手动入口；启动等待页按 Web/Controller/OpenClaw/模型 ready blockers 和本地 runtime unit phase 给出用户可读状态，并提供“重试启动”和“导出诊断包”。连续冷启动失败或 OpenClaw sidecar 完整性标记缺失时重置/重解压可重建 sidecar。所有用户可见兜底界面必须保持 Claw-Pi/龙虾品牌，不暴露 `nexu` 等内部工程名。
* User-facing error taxonomy：Controller、Web 和诊断导出使用统一错误分类，把模型网络、上游饱和、余额不足、登录过期、模型认证缺失、OpenClaw 未就绪、图片返回丢失、附件解析失败、微信扫码等待等已知失败映射为明确中文文案；已知失败不得退化为“没有收到有效回复”。诊断包根目录写入 `diagnosticsSummary.json`，供售后直接判断本地、账号、余额、上游、图片或微信链路问题。
* Recharge UX policy：用户侧充值页只展示余额、充值入口、待支付订单和充值记录，不展示模型定价、token 明细或消费日志；余额接口失败统一提示“余额暂时无法显示，请检查网络后重试”，并提供手动刷新。

== 6. 运行时视图

=== 6.1 工作台对话

[source,text]
----
Workbench UI
  -> POST /api/internal/agent-chat/stream
  -> requestRoute selects lightweight chat vs read/write/image prompt
  -> Web sidecar uses long-running timeout for this stream route
  -> AgentChatService creates SSE immediately
  -> skip OpenClaw preflight if a successful sync is already known
  -> Controller emits SSE keepalive comments while OpenClaw/tool work is silent
  -> wait until OpenClaw WS connected if needed
  -> ws.request("agent", sessionKey, message, thinking="off", bootstrapContextMode="lightweight")
  -> OpenClaw dispatches agent turn
  -> Model provider link/gpt-5.5
  -> OpenClaw emits chat delta/final
  -> Controller maps events to SSE chunks
  -> UI renders assistant reply
----

=== 6.2 生图

[source,text]
----
User asks image generation
  -> OpenClaw tool image_generate
  -> plugin validates prompt/inputImages and logs tool_call inputImagesCount
  -> if image-to-image/edit intent has no inputImages, return missing_input_images without cloud call
  -> clawpi-image-generation runtime plugin
  -> Controller /api/internal/desktop/images/generations
  -> cloud image model clawpi-image/gpt-image-2
  -> text-to-image uses stream=true, partial_images=1
  -> image-to-image/edit uses sync /v1/images/edits
  -> if text-to-image stream returns 406 openai_error, retry once with sync mode
  -> Controller logs endpoint/model/input-image/count/duration/status for the cloud image call
  -> parse final SSE image event for text-to-image; if the stream breaks after a partial image, save the latest partial as fallback
  -> generated image stored under nexu-home/generated-images
  -> markdown image URL returned to UI
----

=== 6.3 OpenClaw 启动

[source,text]
----
Desktop starts Controller
  -> Controller writes OpenClaw config
  -> OpenClawProcessManager spawns OpenClaw
  -> env includes OPENCLAW_SKIP_MODEL_PRICING=1
  -> Controller WS client retries until gateway is ready
  -> workbench stream waits internally if user sends message early
----

=== 6.4 Model Catalog 快路径

[source,text]
----
Controller compileModelsConfig
  -> OpenClaw config models.mode = "replace"
  -> OpenClaw config models.providers.link.models includes gpt-5.5
  -> patched models-config skips implicit provider discovery
  -> patched model-catalog builds entries directly from explicit providers
  -> OpenClaw agent selects link/gpt-5.5
  -> nexu-runtime-model calls 云雾/Link model API
----

这个路径只影响 OpenClaw sidecar 的模型发现阶段，不改变龙虾大脑、微信/飞书渠道和 `/v1/chat/completions` 的兼容路径。

=== 6.5 Desktop Surface 生命周期

[source,text]
----
默认用户路径:
  Web 工作台 /workspace
  -> SurfaceFrame mountWhenInactive=true
  -> 切到其他桌面页时短时间保留输入、附件预览、滚动和会话 UI 状态
  -> inactive 超过保留窗口后卸载 webview，释放隐藏页面内存

诊断/调试路径:
  OpenClaw 原生 /chat
  -> SurfaceFrame mountWhenInactive=false
  -> 只有 activeSurface=openclaw 时挂载 webview
  -> inactive 后卸载 webview，释放 OpenClaw Chat 页面内存

崩溃路径:
  webview render-process-gone
  -> SurfaceFrame 记录 reason/exitCode
  -> 显示“页面进程已崩溃”和“重新加载”
  -> 用户触发后重新挂载 webview
----

该策略优先保护普通用户使用 Web 工作台的连续性，同时减少非主流程 OpenClaw 原生页在后台常驻造成的 OOM 风险。

=== 6.6 桌面冷启动恢复

[source,text]
----
Electron main
  -> Windows 在 requestSingleInstanceLock() 前清理同安装目录旧 Claw-Pi.exe
  -> allocateDesktopRuntimePorts()
  -> Windows 检查并清理 50800 / 50810 / 18789 的占用 PID
  -> 固定使用 Controller/Web/OpenClaw 默认端口
  -> createMainWindow()
  -> renderer 等待 /api/internal/desktop/ready
  -> web/desktop 未 ready 时停留在龙虾工作台启动界面继续等待
  -> 等待页读取 runtime:get-state + /desktop/ready blockers 显示用户可读状态
  -> 用户需要排查时手动进入启动状态/诊断页

连续冷启动失败:
  StartupHealthCheck unhealthy
  -> packaged mode 重置 data/user-data/runtime/openclaw-sidecar
  -> 下次 extractOpenclawSidecarAsync() 从 resources/runtime/openclaw 重新解压

OpenClaw sidecar 完整性:
  -> 解压到 staging 目录并验证 openclaw.mjs
  -> 替换目标目录后写入 .archive-stamp 和 .extract-complete.json
  -> 标记缺失、归档指纹不匹配或入口文件缺失时重新解压
----

该恢复路径只清理可重建的 OpenClaw sidecar 解压目录，不清理 `nexu-home`、聊天状态、模型配置或用户上传文件。

== 7. 部署视图

当前目标部署形态是 Windows portable：

* 可执行文件：`apps/desktop/release/win-unpacked/Claw-Pi.exe`
* Controller bundle：`resources/runtime/controller/dist/index.js`
* OpenClaw sidecar：`resources/runtime/openclaw/node_modules/openclaw`
* Standalone Node runtime：`resources/runtime/node/bin/node.exe`
* OpenClaw archive payload：Windows 使用 `resources/runtime/openclaw/payload.zip`，避免 7z/LZMA 在 OneDrive 路径下长时间卡住。
* 用户数据：`apps/desktop/release/win-unpacked/data`
* OpenClaw 状态：`data/user-data/runtime/openclaw/state`
* Claw-Pi 配置：`data/nexu-home`

打包命令：

[source,powershell]
----
$env:NEXU_DESKTOP_USE_EXISTING_BUILDS='1'
$env:NEXU_DESKTOP_USE_EXISTING_RUNTIME_INSTALL='1'
pnpm --filter @nexu/desktop dist:win:portable
----

Windows 自动更新发布形态使用 NSIS 安装包，而不是 portable 包。发布命令为：

[source,powershell]
----
pnpm --filter @nexu/desktop dist:win
----

发布到更新源时必须同时上传 `claw-pi-setup-<version>-x64.exe`、对应 `.blockmap` 和 `latest.yml` 到 `https://api.claw-pi.cn/updates/stable/x64/`。Windows 打包脚本会把默认更新源写入 `build-config.json`，避免客户端回落到旧的 `api.clawpi.app:9443` 更新源。上传后执行：

[source,powershell]
----
pnpm verify:update-feed -- --expected-version <version>
----

该检查会读取远端 `latest.yml`，验证安装包和 blockmap 可访问，并在完整模式下下载安装包计算 sha512，避免用户侧更新失败或下载到损坏安装包。

Windows 自动更新安装必须经过桌面端 `UpdateManager.quitAndInstall()` 的托管流程：先停止周期检查、关闭 runtime sidecar、清理 Claw-Pi 旧进程、检查关键目录锁，再触发 NSIS 安装。`autoInstallOnAppQuit` 必须保持关闭，避免用户下载更新后直接退出软件时绕过托管停服流程，导致安装器遇到文件锁或残留进程而更新后打不开。

== 8. 横切概念

=== 8.1 权限模式

工作台历史上支持 `basic`、`confirm`、`full` 三档权限；当前产品权限模型收敛为统一完全访问。前端不再展示权限切换 UI，也不再持久化本地权限选择。Controller 继续接受旧请求字段，但 `permissionMode` 始终归一为 `full`，`executionMode` 始终归一为 `write`，`read_only_agent` 仅作为旧协议兼容值，不再代表只读行为。真实阻塞只来自工具、上游、余额、认证或网络失败。

=== 8.2 Session Key

工作台 session 映射为：

[source,text]
----
agent:{agentId}:workbench:{sessionId}
----

该 key 必须稳定，才能让 OpenClaw 恢复同一会话上下文。

=== 8.3 模型选择

默认模型来自桌面当前选择；若未设置，则回退到 bot 模型或 runtime 默认模型。当前测试要求只使用：

* 对话：`link/gpt-5.5`
* 生图：`clawpi-image/gpt-image-2`

=== 8.4 Latency 分层

必须区分：

* HTTP/SSE header 建立时间。
* OpenClaw WS request ack 时间。
* OpenClaw session-init/dispatch 时间。
* LLM 首字时间。
* OpenClaw final event 到 UI 完成时间。

== 9. 架构决策

=== ADR-016: Gateway 鉴权同时携带 gateway token 和 device token

*状态：已采纳*

原因：打包版运行时可能同时存在配置级 gateway token 和本机已保存的 device token。旧逻辑在 gateway token 存在时不发送 device token，诊断包中出现 `hasGatewayToken=true, hasStoredDeviceToken=true, hasResolvedDeviceToken=false`，随后 OpenClaw Gateway 返回 `NOT_PAIRED / pairing required`。这会让 OpenClaw WS 无法稳定 connected，并连带影响微信通道连接、渠道同步和 agent 执行路径。

结果：`OpenClawWsClient` 在发起 `connect` 请求时始终读取已保存的 device token；gateway token 仍作为 `auth.token`，device token 作为 `auth.deviceToken` 一并发送。旧客户端或未配对设备没有 device token 时仍沿用原有 gateway token 行为。

=== ADR-001: 工作台走 OpenClaw runner

*状态：已采纳*

原因：工作台需要本机执行权、文件处理、技能、工具和 OpenClaw session。直连 `/v1/chat/completions` 只能提供普通聊天。

结果：新增 Controller `AgentChatService`，使用 OpenClaw `agent` runner。

=== ADR-005: 工作台使用 OpenClaw `agent` 方法并启用 lightweight bootstrap

*状态：已采纳*

原因：`chat.send` 是 WebChat 专用 schema，不接受 `extraSystemPrompt` 和 `bootstrapContextMode`。工作台需要跳过新工作区 bootstrap/onboarding 上下文，同时保留 OpenClaw runner、工具和会话能力。

结果：工作台改为调用 OpenClaw `agent` 方法；sessionKey 继续使用 `agent:{agentId}:workbench:{sessionId}`；请求设置 `deliver=false`、`thinking=off`、`bootstrapContextMode=lightweight`。

=== ADR-002: 保留兼容直连模型接口

*状态：已采纳*

原因：上下文压缩、诊断工具、旧路径和第三方兼容调用仍依赖 OpenAI-compatible 接口。

结果：工作台/网页龙虾用户发送路径走 OpenClaw-backed `/api/internal/agent-chat/stream`；迁移不删除 `/v1/chat/completions`，但不能把它当作主问答 runner。

=== ADR-008: Web 龙虾大脑不做直连降级

*状态：已采纳*

原因：用户体验要求 Web 龙虾大脑、工作台和原生 OpenClaw 保持同一套 runner 语义，避免普通问答、文件处理和生图割裂。

结果：Web 龙虾大脑所有请求统一走 OpenClaw `agent` runner，固定 `full` 权限和可写执行模式。明确生图/图生图仍由 OpenClaw 决策并调用 `image_generate`，最终落到 Controller `/api/internal/desktop/images/generations` 和 `clawpi-image/gpt-image-2`。不新增绕过 OpenClaw 的直连生图降级路径。

=== ADR-003: 禁用 OpenClaw pricing bootstrap

*状态：已采纳*

原因：OpenRouter pricing catalog 网络超时会阻塞首条工作台消息。

结果：OpenClaw sidecar patch 支持 `OPENCLAW_SKIP_MODEL_PRICING=1`，Controller 启动 OpenClaw 时注入该环境变量。

=== ADR-004: SSE 先建立，再等待 OpenClaw ready

*状态：已采纳*

原因：OpenClaw 冷启动或 WS 鉴权可能耗时较长，若 Controller 在返回 Response 前等待，会让 UI 看起来无响应。

结果：`AgentChatService` 创建 `ReadableStream` 后立即返回 Response，后台等待 Gateway connected。

=== ADR-006: Web 工作台延迟释放，OpenClaw 原生页按需挂载

*状态：已采纳*

原因：诊断包中出现多次 Electron embedded webview OOM。直接卸载所有 inactive webview 会影响习惯使用 Web 工作台的用户，造成输入框内容、附件预览、滚动位置和未完成操作状态丢失。

结果：主 Web 工作台 active 时保持连续使用体验；inactive 后保留短窗口，超过窗口则卸载 webview。OpenClaw 原生调试页 inactive 时立即卸载。`SurfaceFrame` 增加 `mountWhenInactive` 和 `inactiveUnmountDelayMs` 控制，并在 `render-process-gone` 时显示可重载错误态。

=== ADR-007: Readiness 状态分层，禁止全局 OpenClaw gate

*状态：已采纳*

原因：桌面壳、Web 工作台、OpenClaw gateway、agent 模型和微信/外部渠道的可用性不同步。若用一个 `openclawReady` 阻塞所有入口，OpenClaw 配置或 WS 问题会连带让 Web 和诊断能力不可用；若把 health probe disabled 当 healthy，则 UI 会出现假就绪。

结果：`/api/internal/desktop/ready` 保留兼容 `ready=true`，同时返回 `desktopReady`、`webReady`、`openclawReady`、`agentReady`、`channelsReady` 和 `blockers`。桌面端用该接口更新 OpenClaw 原生页状态；Web 工作台只依赖 `desktopReady/webReady` 打开，发送 agent 任务时再由 SSE 后台等待或暴露 blocker。

=== ADR-008: OpenClaw runtime plugin staging 不进入 extensions

*状态：已采纳*

原因：OpenClaw 会扫描 `extensions` 目录下的插件。若 Controller 把 `.staging-*` 临时目录放在该目录内，启动或热 reload 可能读到缺失 `openclaw.plugin.json` 的半成品目录，导致 `Config invalid` 和 gateway 无法就绪。

结果：runtime plugin copy staging 改到 `openclawStateDir/tmp/plugin-staging`；`ensurePlugins()` 启动时清理历史 `extensions/*.staging-*` 目录。

=== ADR-018: OpenClaw 本机执行自修复分级

*状态：已采纳*

原因：覆盖安装、旧 OpenClaw state 或执行 host 残留可能让本机执行落到 `node` host，但桌面包没有 paired node，表现为 `exec host=node requires a paired node (none available)`、`/approve`、命令无法执行或后续无回复。若每次错误都全量 stop/reset/start OpenClaw，Web 工作台会频繁显示“服务启动中”。

结果：Controller 编译 OpenClaw config 时固定 `tools.exec.security=full`、`tools.exec.ask=off`、`tools.exec.host=auto`。`AgentChatService` 将 paired-node、approval、host mismatch、gateway not ready 等错误交给 `OpenClawRuntimeRepairCoordinator`；协调器同一时间只执行一个修复任务，优先 `syncAllImmediate()` 软修复，必要时清理 config/approval/tmp/cache 并重启 OpenClaw，深修复带 5 分钟冷却。修复不会删除云端登录、余额或 OpenClaw sessions，并把最近 session 线索写入 `nexu-runtime-repair-summary.json`。

=== ADR-009: 冷启动停留在品牌启动界面

*状态：已采纳*

原因：部分用户无法打开时，问题可能发生在 Web sidecar、OpenClaw sidecar、ready 接口或端口分配阶段。自动切到诊断/修复页虽然方便排查，但会让普通用户看到内部启动控制界面，误以为进入了错误软件。

结果：Windows 启动前固定清理 `50800`、`50810`、`18789` 的监听进程，并继续使用固定端口，不再静默漂移到 OS ephemeral port；renderer 获取 runtimeConfig 后持续轮询 `/api/internal/desktop/ready`，未 ready 时继续停留在龙虾工作台启动界面，不自动切到启动状态或诊断页。等待页额外读取 `runtime:get-state`，把本地 unit phase 和 ready blockers 翻译成“正在启动/本地服务未响应/OpenClaw 网关正在连接/默认模型正在同步/组件启动异常”等用户可读状态，并提供手动“重试启动”和“导出诊断包”。启动状态、日志导出和 runtime 单元操作能力仍作为手动入口保留；这些页面使用 Claw-Pi/龙虾用户可见文案，runtime 单元 label 不暴露 `nexu Web Surface`、`nexu Controller` 等内部名。

=== ADR-010: 连续失败后重置可重建 sidecar

*状态：已采纳*

原因：覆盖安装或异常退出可能留下损坏的 `data/user-data/runtime/openclaw-sidecar` 解压目录，但 `.archive-stamp` 仍匹配，导致后续启动持续复用损坏 runtime。

结果：`StartupHealthCheck` 判定连续冷启动失败后，packaged mode 删除可重建的 `openclaw-sidecar` 和 `.staging` 目录；正常启动时要求 `.archive-stamp` 和 `.extract-complete.json` 同时有效，缺失或不匹配则从随包资源重新解压。用户配置、聊天、模型和附件目录不被清理。

=== ADR-011: Packaged OpenClaw 使用 standalone Node 和 ZIP payload

*状态：已采纳*

原因：packaged 环境中使用 `Claw-Pi.exe` 的 Electron-as-Node 启动 OpenClaw gateway 时，实测会在 gateway listen 前卡住；同一份 sidecar 使用 standalone `node.exe` 可正常 ready。同时 Windows/OneDrive 工作目录下 7z/LZMA 压缩 OpenClaw node_modules 可能长时间不退出，阻塞发版。

结果：Windows release 将构建机 `node.exe` 复制到 `resources/runtime/node/bin/node.exe` 并签名；Controller 通过 `OPENCLAW_NODE_EXECUTABLE` 优先用该 Node 启动 OpenClaw，缺失时才回退 Electron-as-Node。Windows OpenClaw sidecar payload 改为 `payload.zip`，保留 `payload.7z` 解压兼容以支持旧包。

=== ADR-012: Agent 请求前同步 OpenClaw 配置和 `main` 凭证

*状态：已采纳*

原因：Web 龙虾大脑使用 OpenClaw 隐式 `main` agent，工作台和微信端使用具体 bot agent。旧同步只给 `agents.list` 中的 bot workspace 写 `auth-profiles.json`，`main` agent 可能缺少 `link:default`，从而出现 `No API key found for provider "link"`。但稳定态每 10 秒重复完整 preflight 会额外写配置、触发 OpenClaw reload，并拉长简单回复首字时间。

结果：`OpenClawAuthProfilesWriter` 永远给 `agents/main/agent/auth-profiles.json` 和所有 active bot workspace 写入同一套 provider profiles。`OpenClawSyncService` 记录最近成功/失败同步状态和正在执行的同步 Promise；`AgentChatService` 只在未成功同步、上次同步失败或已有同步进行中时等待 preflight。若同步或凭证失败，SSE 返回明确中文错误，不再退化成“没有收到有效回复”。

=== ADR-013: `gpt-image-2` 使用流式生图请求

*状态：已采纳*

原因：诊断包显示 `gpt-image-2` 同步 `/v1/images/generations` 请求多次在约 61s 后被对端关闭 socket，Controller 本地 180s 超时并未触发。这说明问题是上游/代理在长时间无首包时断开，而不是 OpenClaw 权限、插件注册或余额问题。

结果：Controller 对 `gpt-image-2` 纯文生图 generation 请求默认添加 `stream=true` 和 `partial_images=1`，解析 SSE final image event 后保存图片。若云端明确返回 streaming 参数不支持，或返回 `406 openai_error`，退回原同步请求重试一次。图生图/改图 edit 请求固定同步调用 `/v1/images/edits`，因为诊断包显示云雾 edit stream 会返回 `500` 和 `Syntax error ... event: image_edit.completed`。

=== ADR-015: 图生图缺少 `inputImages` 时阻断云端请求

*状态：已采纳*

原因：OpenClaw 原生聊天页里，聊天模型可能能看到用户上传图片，但 `image_generate` 工具调用未必能拿到这张图的本机路径或 data URL。诊断包显示 `nexu-runtime-model` 输入有 `images=1`，但 Controller 生图请求为 `hasInputImages=false,inputImageCount=0`，导致基于图片的请求误走 `/v1/images/generations`，最终云雾返回 `406 openai_error` 或长时间超时。

结果：`clawpi-image-generation` runtime plugin 在工具调用前判断 prompt/mode/task 是否为图生图、改图、修图、参考图等意图；若 `inputImages` 为空，返回 `missing_input_images`，并提示用户通过龙虾工作台附件流上传或提供本机路径/URL。后续若 OpenClaw 原生上传能暴露本机路径，可由 plugin 自动补齐 `inputImages`。

=== ADR-014: AgentChat route-aware lightweight prompt

*状态：已采纳*

原因：全部入口统一走 OpenClaw 后，普通寒暄也带着文件/网页/生图/可写执行提示、历史摘要和最近多轮上下文进入 agent，导致首字慢且容易把简单问答误判成执行任务。

结果：`/api/internal/agent-chat/stream` 增加内部 `requestRoute` 字段。后续产品策略改为除 `image_generation` 外统一走全能力 `write_agent`；旧的 `chat`、`read_only_agent` 字段继续兼容接收，但不再禁用工具或自动续跑。前端不再把历史摘要和最近 8 条重复注入当前消息，附件正文由 Controller 保存/提取后注入。

=== ADR-017: Agent 上下文和续跑预算保守化

*状态：已采纳*

原因：全部入口统一走 OpenClaw 后，长 session 记忆、附件正文、工具输出和自动续跑会叠加放大每轮模型输入，用户反馈余额消耗过快。过度削减又会让工作台回到“需要用户一直继续”的僵硬体验。

结果：OpenClaw compaction 默认 `keepRecentTokens=8000`；工作台附件正文提取最多注入 12000 字符；进度自动续跑最多 4 次；空回复重试保留 1 次。该策略优先保证任务能持续执行，余额消耗控制不再通过产品权限软约束实现。

== 10. 质量需求

=== 10.1 质量场景

[cols="1,2,2",options="header"]
|===
|质量属性 |场景 |验收方式

|响应性
|工作台发送简单消息时，HTTP/SSE header 快速返回。
|本地测试 headerMs 小于 200ms。

|稳定性
|OpenClaw 冷启动期间发送消息不会直接 502。
|SSE 建立，后台等待 OpenClaw ready。

|凭证就绪
|Web 龙虾大脑、工作台或微信端首次请求时，`link/gpt-5.5` 凭证必须已同步到 `main` 和 bot agent。
|首次或失败后请求前出现 `agent_chat_preflight_sync_complete`；稳定态可出现 `agent_chat_preflight_sync_skipped`；若缺失凭证，用户看到模型账号未就绪提示而非原始 OpenClaw 错误。

|上游错误可见性
|OpenClaw `chat` event 返回 `state=error`，错误为 `network connection error` 或 `Connection error`。
|Controller SSE 输出标准化错误“模型连接失败，请稍后重试。”并正常结束，不再显示“没有收到有效回复”。

|错误可解释性
|OpenClaw、云雾、图片、充值或微信链路返回已知失败。
|Web 和 Controller 按统一分类显示“模型连接失败，请稍后重试。”、“上游分组负载饱和，请稍后再试”、“余额不足，请及时充值”、“登录状态已过期，请重新登录”、“模型账号未就绪，请重新登录或检查云雾连接。”、“OpenClaw 本地服务未就绪，正在重试。”或“图片生成已提交但结果返回失败，请查看诊断。”，不暴露原始堆栈和内部服务名。

|售后诊断性
|用户导出诊断包后，售后需要无需复现就判断大方向。
|诊断包包含 `diagnosticsSummary.json`，字段包括 version、lastRunId、lastErrorCategory、startupStatus、openclawReady、modelAuthReady、imagePluginReady、balanceStatus 和 wechatStatus，并给出一句话结论。摘要分类必须覆盖生图 `openai_error`、余额接口不可用、登录过期、微信扫码等待和微信网络异常，避免售后只能看到 `unknown`。

|余额可用性
|充值页余额接口因为网络、登录状态或云端短暂异常加载失败。
|页面显示“余额暂时无法显示，请检查网络后重试”，保留刷新余额按钮；登录过期则引导重新登录；用户侧不展示 token、模型定价和消费日志。

|功能正确性
|工作台回复来自 OpenClaw agent path。
|日志出现 `agent` request、OpenClaw `chat` event、`nexu-runtime-model`。

|生图正确性
|OpenClaw 原生/agent 生图和 Web 龙虾大脑生图都使用 `gpt Image2`。
|Controller image generation 对纯文生图通过 streaming 避免 60s 无首包断连，返回 200 并生成 PNG；若 stream 返回 `406 openai_error`，同步重试一次。图生图/改图使用同步 `/v1/images/edits`，不带 `stream`/`partial_images`。图生图/改图缺少 `inputImages` 时不提交云端请求。

|生图可诊断性
|云端图片接口可能在 60s-180s 内断开本地响应，但上游已经扣费。
|`clawpi-image-generation` 记录 `tool_call` 的 prompt 长度和 `inputImagesCount`；`image_generation_cloud_response` 记录 `requestMode=stream/sync`；`image_generation_response_lost` 记录 endpoint、模型、是否图生图、输入图片数量、timeout、elapsedMs、error/cause code；`image_generation_stream_completed` 记录 partial/final 解析结果。

|长任务流稳定性
|工作台生图、图生图、文件处理等长任务可能超过 120s。
|Web sidecar 对工作台 stream 和生图接口使用长任务超时；Controller SSE 定期发送 keepalive，最终结果仍能回到 UI。

|可打包性
|修复必须进入 portable 包，而不是手工改 release 目录。
|`dist:win:portable` 成功，sidecar patch 日志出现。

|桌面稳定性
|后台 OpenClaw 原生页和长期隐藏 Web 工作台不应持续占用 webview 进程内存。
|切换到 Web 后 OpenClaw surface inactive 时不挂载 webview；Web surface inactive 超过保留窗口后卸载；若 webview 崩溃，UI 显示可重载错误态。

|启动可诊断性
|Controller/Web/OpenClaw 任一 sidecar 卡住时，桌面壳仍应保留品牌化主启动界面，并允许用户手动进入启动状态/诊断页。
|非显式端口冲突回退 ephemeral port；ready 超时不自动切到诊断/修复页；启动等待页显示用户可读状态并提供重试/导出；连续冷启动失败后重置可重建 OpenClaw sidecar；packaged OpenClaw 使用随包 standalone Node 启动。
|===

== 11. 技术风险

[cols="1,3,2",options="header"]
|===
|风险 |说明 |处理策略

|OpenClaw 冷启动慢
|replace-mode model catalog 已降到毫秒级，但 OpenClaw 进程启动、WS connected 和外部模型 API 仍可能导致首条请求几十秒等待。
|继续记录 `agent_chat_gateway_ready`、`openclaw_ws_connected`、`first_text`，后续优化 process startup/session-init。

|Gateway health 与 WS 状态短暂不一致
|冷启动时 health 可能已响应，但 Controller WS 尚未完成握手；probe disabled 时也不能当成 ready。
|`openclawReady` 必须同时参考 health/probe 状态和 `OpenClawWsClient.isConnected()`；`AgentChatService` 仍在 SSE 后台等待 `agent_chat_gateway_ready`。

|Gateway 配对凭证丢失
|打包环境已有 device token 但连接时只发送 gateway token，会在 admin/scope-upgrade 场景触发 `NOT_PAIRED`，表现为微信连接后无响应或 OpenClaw agent 无法 ready。
|Gateway WS 鉴权同时发送 `auth.token` 和 `auth.deviceToken`；日志继续保留 `hasGatewayToken`、`hasStoredDeviceToken`、`hasResolvedDeviceToken` 用于诊断。

|配置热 reload 抖动
|Controller 多次写 OpenClaw config 可能触发 reload，占用事件循环。
|已限制首次 WS connected 后的重复 `syncAll()`；后续继续减少无差异写入，增加 config fingerprint 去重。

|Runtime plugin 半成品目录
|如果 staging 留在 OpenClaw extensions 扫描目录内，OpenClaw 可能把半成品目录当插件加载并导致 gateway 无法 ready。
|staging 移到 `openclawStateDir/tmp/plugin-staging`，启动时清理历史 `.staging-*` 残留。

|Webview 生命周期切换
|卸载 inactive webview 可释放内存，但若用于主工作台会丢失输入、附件预览、滚动位置和正在接收的流式回复。
|OpenClaw 原生调试页 inactive 立即卸载；Web 工作台 inactive 延迟卸载。后续若需要缩短保留窗口，必须先持久化草稿、附件和运行中任务状态。

|Webview OOM 复现
|如果 OOM 根因来自主 Web 工作台本身，卸载 OpenClaw 原生页只能降低概率，不能完全消除。
|保留 `render-process-gone` 可见错误态，并对长期 hidden Web surface 做延迟释放；继续用诊断包统计 `reason=oom` 频率，必要时进一步拆分工作台资源或实现 Web surface 安全恢复。

|Windows 旧进程或固定端口被占用
|旧 `Claw-Pi.exe` 若仍持有 single-instance lock，新实例会在端口清理前退出；残留 Controller/Web/OpenClaw 进程也可能占用固定端口，导致组件互相连接到旧进程。
|Windows 在 `requestSingleInstanceLock()` 前用 `wmic` 查找同安装目录或 `claw-pi-desktop` 上下文的旧 `Claw-Pi.exe` 并 `taskkill /F /T`；随后使用 `netstat -ano -p tcp` 定位 `50800`、`50810`、`18789` 的监听 PID 并清理。提供 `NEXU_DESKTOP_DISABLE_MAIN_PROCESS_RECLAIM=1` 和 `NEXU_DESKTOP_DISABLE_PORT_RECLAIM=1` 作为调试逃生开关。

|Sidecar 解压目录损坏
|`.archive-stamp` 匹配但实际 node_modules 或 OpenClaw 文件损坏时，普通快速路径会继续复用损坏目录。
|解压完成后写入 `.extract-complete.json`；标记缺失、归档指纹不匹配或入口文件缺失时重新解压。连续冷启动失败后只删除可重建 `openclaw-sidecar` 解压目录，保留用户配置和数据。

|Packaged Node 体积和平台匹配
|随包发布 `node.exe` 会增加 Windows 包体积，且必须匹配目标架构。
|Windows 当前只打 x64 包；构建时复制当前 Node runtime，冷启动烟测确认 OpenClaw 进程命令行使用 `resources/runtime/node/bin/node.exe`。

|ZIP payload 体积
|`payload.zip` 比高压缩 7z 更大，可能增加下载体积。
|接受该体积换取可预测打包和安装解压；若未来需要缩小体积，应在非 OneDrive 临时目录中做 7z 压缩并设置超时/失败回退。

|附件能力不足
|当前已保存附件，但 DOCX/PPTX/XLSX/PDF 的深度解析仍需补齐。
|后续按文件类型逐步接入文档解析和 OpenClaw tool 读取。

|生图响应丢失
|云端图片接口可能已经生成并扣费，但本地 fetch 在读取响应时断开，导致没有可保存图片。
|`gpt-image-2` 纯文生图使用 streaming + partial image progress 降低 60s 断连概率；若 stream 读取中断但已有 partial，则保存最新 partial。图生图/改图不使用 edit stream，避免云雾 edit stream 返回 500/SSE syntax error，并记录 `requestMode=sync`。

|上下文预算与自动续跑
|`keepRecentTokens=8000` 和附件正文 12000 字符仍可能让长对话忘记更早背景，自动续跑提高到 4 次会增加复杂任务的 token 和工具消耗。
|当前优先保证任务持续执行和减少“没有收到有效回复”；后续若余额消耗再次成为主风险，应通过上游分组、模型价格和诊断账单优化，而不是恢复产品权限软限制。

|错误分类误判
|统一错误分类依赖上游返回文本和本地日志特征。若上游文案变化，可能把未知错误归入相邻类别，影响用户提示和售后判断。
|分类只对高置信关键字生效，未知错误保留原始摘要到日志和诊断包；新增上游错误样本后补测试，避免把真实链路故障误报成余额或用户操作问题。

|OpenClaw 原生上传图片不能直接变成 `inputImages`
|原生聊天页上传图片可能只进入对话模型视觉上下文，而不会暴露给 `image_generate` 工具为本机路径/URL。
|插件对图生图/改图意图且 `inputImages` 为空的请求返回 `missing_input_images`，避免误走纯文生图；推荐用户走龙虾工作台附件上传，或提供本机图片路径/URL。后续若 OpenClaw 原生页提供附件路径 hook，再改为自动补齐。

|侧车补丁维护成本
|OpenClaw dist 文件名和 anchor 可能随上游版本变化。
|patch 脚本必须 anchor 校验；升级 OpenClaw 时先跑 sidecar prepare。

|权限边界
|统一完全访问会提升误执行风险，尤其是用户表达含糊但 agent 推断为写入、打开或运行任务时。
|不再通过 `basic/confirm/read_only` 提示词限制 agent；产品层依赖工具真实失败、系统权限、诊断日志和后续更明确的用户可撤销/备份机制控制风险。
|===
