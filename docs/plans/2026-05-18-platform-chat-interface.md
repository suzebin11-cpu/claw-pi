# SaaS 平台内置问答界面需求与实施方案

## 背景

当前 SaaS 工作区里已有两类问答入口：

- Web 端运行时界面：通过侧边栏“运行界面”打开独立的 OpenClaw Chat 页面。
- 微信端：用户扫码连接后，通过微信消息触发模型问答。

问题是平台工作区内部没有一个可以直接对话的页面。用户需要在模型广场、连接状态、会话历史和外部运行界面之间来回切换，体验不连续。

本次新增一个平台内置问答界面，暂定名称为“即时问答”，路由为 `/workspace/ask`。

## 目标

- 在 SaaS 工作区侧边栏新增“即时问答”入口。
- 用户进入该页面后，可以直接输入问题并得到模型回复。
- 页面内支持切换模型。
- 页面模型选择与模型广场共享同一份当前模型状态：
  - 在即时问答页切换模型，模型广场应显示同一当前模型。
  - 在模型广场切换模型，即时问答页应跟随更新。
- 支持上传附件：
  - 图片：尽量作为多模态内容传给模型。
  - 文本类文件：读取文本内容后附加给模型分析。
  - 视频和其他二进制文件：先作为附件元信息和可预览对象进入消息，实际模型处理能力取决于所选模型和兼容接口支持。
- Web 端问答采用流式显示，降低首字等待感。
- 不影响现有 Web 运行界面、微信连接、微信问答、会话历史和模型广场原有流程。

## 非目标

- 不重写微信消息链路。
- 不替换现有 OpenClaw Chat 页面。
- 不改变模型广场的模型配置、鉴权和提供商管理逻辑。
- 不在第一版里承诺所有模型都能理解视频内容；视频处理能力需要模型和上游接口同时支持。
- 不在第一版里把平台内置问答强行并入微信历史会话，避免污染用户现有渠道历史。

## 现有链路评估

### 模型状态

现有模型状态来源：

- 当前模型读取：`GET /api/internal/desktop/default-model`
- 当前模型写入：`PUT /api/internal/desktop/default-model`
- 可选模型列表：`GET /api/v1/models`
- 前端已有复用组件：`ModelPickerDropdown`
- 首页/状态栏已有复用逻辑：`InlineModelSelector`

结论：

新增页面应复用这些 API 与 React Query key：

- `["desktop-default-model"]`
- `["models"]`

这样模型广场切换后，新页面可以通过同一 query 状态同步；新页面切换模型后，也可以让模型广场读到一致状态。

### 问答入口

控制端已有 OpenAI-compatible 路由：

- `POST /v1/chat/completions`

该路由会：

- 从运行时模型状态读取当前模型；
- 读取当前模型 provider/baseUrl/apiKey；
- 代理到中转站或用户配置的 OpenAI-compatible 上游；
- 支持 `stream: true`；
- 当前对 DingTalk compat session 做了历史补全和 transcript 追加。

结论：

新增页面第一版应优先使用 `/v1/chat/completions`，避免新增一套模型调用逻辑，也避免出现“模型广场选 A，新页面偷偷用 B”的问题。

### 会话历史

现有 SaaS 会话页主要用于展示渠道会话历史：

- `GET /api/v1/sessions`
- `GET /api/v1/sessions/{id}`
- `GET /api/v1/sessions/{id}/messages`

第一版不把即时问答写入渠道会话历史。原因：

- 当前 session runtime 更偏渠道历史展示，不是通用平台内聊天线程。
- 强行写入会让侧边栏会话列表混入一个新的伪渠道，容易影响旧 Web/微信体验。
- 内置问答可以先在前端维持当前页面会话；后续再独立设计“平台问答历史”。

## 用户体验需求

### 页面布局

- 页面名称：即时问答。
- 侧边栏位于“首页”和“运行界面/模型广场”附近，便于用户把它理解为平台内直接问答入口。
- 主区域是聊天界面，不做介绍页或营销页。
- 顶部显示：
  - 页面标题；
  - 当前模型选择器；
  - 简短状态，例如“当前模型已同步模型广场”。
- 中间为消息列表：
  - 用户消息右侧；
  - 助手消息左侧；
  - 支持 Markdown 渲染；
  - 流式回答时实时追加内容。
- 底部为输入区：
  - 多行文本输入；
  - 附件按钮；
  - 发送按钮；
  - 附件预览/移除。

### 附件体验

- 图片文件：
  - 展示缩略图；
  - 发送时转为 `image_url` content block。
- 文本类文件：
  - 读取文本，限制单文件最大读取长度；
  - 在提示词中以文件名和内容片段形式传给模型。
- 视频文件：
  - 展示文件卡片和大小；
  - 第一版不主动把大视频转 base64 塞进请求，避免卡顿和请求过大；
  - 如果后续确认上游模型支持视频 data URL，再单独加开关。
- 其他文件：
  - 展示文件名、类型、大小；
  - 第一版只传元信息，避免用户误以为所有二进制文件都已被完整解析。

### 速度体验

- Web 端使用流式输出。
- 发送后立即把用户消息显示在列表中。
- 模型首个 token 到达前显示轻量加载状态。
- 不引入额外的固定等待、轮询等待或启动探测等待。

## 技术方案

### 前端新增

- 新增页面：`apps/web/src/pages/ask.tsx`
- 新增路由：`/workspace/ask`
- 修改文档标题映射：`title.ask`
- 修改侧边栏：
  - 新增导航入口；
  - 新增移动端标题/副标题；
  - 从空状态判断里排除即时问答页。
- 复用组件：
  - `ModelPickerDropdown`
  - `ChatMarkdown`
  - 现有 `getApiV1Models`
  - 现有 `getApiInternalDesktopDefaultModel`
  - 现有 `putApiInternalDesktopDefaultModel`

### 前端问答请求

使用浏览器 `fetch` 调用：

```ts
POST /v1/chat/completions
{
  model: currentModelId,
  messages: [...localMessages],
  stream: true
}
```

注意：

- 虽然 body 可带 `model`，控制端当前会以运行时模型状态作为最终模型来源。
- 因此发送前如果用户刚在页面切换模型，需要等待 `PUT /api/internal/desktop/default-model` 成功，再发送问题。
- 页面本地维护 messages，用于当前会话上下文，不依赖渠道 session。

### 后端改动

第一版尽量不新增后端路由。

如实现过程中发现 `/v1/chat/completions` 对图片 content block 或非流式错误处理不足，再仅做兼容增强：

- 保持现有路径不变；
- 不改变微信/渠道调用参数；
- 只增强对 `content: Array<unknown>` 的透传和错误返回。

## 风险与卡点

### 1. 附件能力与模型能力不一致

风险：

用户上传视频或复杂文件，但当前模型/中转接口不支持该类型，可能返回错误或无视附件。

处理：

- 第一版 UI 明确按能力分层处理：图片和文本优先支持，视频先作为附件元信息。
- 如果上游返回不支持多模态，页面显示可理解错误，不崩溃。
- 不偷偷换模型。

### 2. 大文件导致页面卡顿或请求过大

风险：

图片、视频、大文档转 base64 会放大体积，可能导致浏览器卡顿、接口超限、响应变慢。

处理：

- 限制单次附件数量。
- 限制文本读取字符数。
- 限制图片 data URL 大小。
- 视频不在第一版直接内嵌完整内容。

### 3. 新页面模型切换影响微信正在使用的模型

风险：

当前系统模型状态是全局默认模型。新页面切换模型后，微信端后续问答也会使用新模型。

处理：

- 这与模型广场现有语义一致：切换默认模型就是切换全局模型。
- 页面内切换使用与模型广场相同的确认弹窗，避免误触。
- 不做页面私有模型状态，避免“看着选了 A，实际全局还是 B”的混乱。

### 4. 平台内置问答历史与渠道历史混淆

风险：

如果第一版把即时问答写进现有 sessions，可能影响侧边栏会话列表和微信/Web 历史。

处理：

- 第一版只保留当前页面内的临时对话上下文。
- 后续如要持久化，应新增独立 channel type 或独立 platform chat session，不复用微信/Web session。

### 5. 生成 SDK 成本

风险：

如果新增后端路由，需要同步 OpenAPI 和前端 SDK，改动面会扩大。

处理：

- 第一版不新增后端 API。
- 如果必须新增，才运行 `pnpm generate-types` 并检查生成文件差异。

## 验收标准

- 侧边栏出现“即时问答”，点击进入 `/workspace/ask`。
- 页面可以看到当前模型。
- 在模型广场切换模型后，回到即时问答页显示同一模型。
- 在即时问答页切换模型后，模型广场显示同一模型。
- 输入短文本可以得到流式回复。
- 上传图片后可随问题一起发送；不支持时页面给出错误提示。
- 上传文本文件后，模型能读取文件内容片段并回答。
- 上传视频时页面不崩溃，不阻塞，不把大视频完整塞进请求。
- 原有 `/workspace/models`、`/workspace/sessions/:id`、微信连接页和运行界面入口仍能正常打开。
- `pnpm --filter @nexu/web build` 通过。
- 如有控制端改动，`pnpm --filter @nexu/controller build` 通过。

## 实施步骤

1. 新增即时问答页骨架和路由。
2. 接入模型列表、当前模型、模型切换。
3. 接入 `/v1/chat/completions` 流式问答。
4. 增加附件选择、预览、删除和发送前转换。
5. 增加 i18n 文案。
6. 验证旧页面不受影响。
